# Every routes（Android アプリ）— 設計書

共通概念・データモデル・同期ルールは [`00-overview.md`](00-overview.md) を参照。本書は Android アプリ固有の設計を扱う。

## 1. 目的

1日の予定・生活ルーティンを、**「1日の過ごし方プロファイル」単位** で管理する Android アプリ。

- 「平日」「休日」などのルーティンプロファイルを作り、曜日・祝日条件で日々に自動適用する
- Google Tasks や AI エージェント（サーバー経由）から入るタスクも統合し、その日の行動をまとめて確認できる
- ホーム画面ウィジェットで、次の予定や今日一覧をアプリを開かず把握できる
- 共有サーバー経由で、機種変更・複数端末でも同じルーティンを引き継げる

## 2. 想定技術スタック（目安）

| 項目 | 方針 |
| --- | --- |
| 言語 | Kotlin |
| 最低 API レベル | Android 8.0 (API 26) 目安 |
| UI | Jetpack Compose |
| ローカル DB | Room |
| バックグラウンド処理 | WorkManager（定期同期）、AlarmManager（時刻境界でのウィジェット更新） |
| ウィジェット | Jetpack Glance |
| 通信 | Retrofit / OkHttp（自己署名証明書の信頼設定を含む） |
| 認証（Google） | Google Sign-In + Tasks API（読み取りスコープ） |

> スタックは実装都合で差し替え可。設計上の要件は「オフラインで完結」「同期は明示的なタイミング」「ウィジェットと本体で今日ビュー計算を共有」。

## 3. 画面構成

### 3.1 今日ビュー（ホーム）

- その日のルーティン（時間帯ブロック）とタスクを **1本の時系列タイムライン** に統合表示（[`00-overview.md`](00-overview.md) §4.3）。
- 現在時刻ライン、進行中ブロックの強調、「次のブロック」「次のタスク」の明示。
- 日付切り替え（前日／翌日／日付選択）。翌日を見ると、エージェントや Google Tasks 由来の先の予定も確認できる。
- タスクはその場で完了操作可能。ルーティンブロックは表示のみ（編集はエディタへ）。
- プルダウンで手動同期。最終同期時刻を表示。

### 3.2 ルーティンプロファイル一覧

- 登録済みプロファイルの一覧（名前、対象曜日／祝日ポリシーの要約、次回適用日）。
- 各項目に「共有済み（ルーティンアドレスあり）」バッジ。
- 新規作成、複製、削除、有効／無効トグル。

### 3.3 ルーティンプロファイル編集

- **名前**（自由入力、重複可）。
- **繰り返し条件**:
  - 曜日チップ（月〜日）。
  - 祝日ポリシー: 祝日は実行しない / 曜日に加え祝日も実行 / 祝日のみ実行（`exclude` / `include` / `only`）。
- **時間帯ブロック**:
  - 追加・編集・削除・並べ替え。
  - 各ブロックは開始時刻・終了時刻（"HH:MM"）・タイトル・メモ。
  - 終了が開始より前なら翌日跨ぎとして扱う旨を表示。
- 画面下部に **最終変更日時**、共有済みなら **ルーティンアドレス**（コピー可）を表示。
- 保存時に `lastModified` を更新（UTC）。

### 3.4 タスク

- タスク一覧（発生源アイコン付き：Google Tasks / エージェント / 手動）。
- 手動タスクの追加・編集・削除・完了。時刻指定（`at`）または「時刻なし（allDay）」。
- Google Tasks 連携の状態表示、今すぐ取得ボタン。
- エージェント由来タスク（サーバー発）は基本読み取り、完了操作はサーバーへ反映。

### 3.5 設定

| セクション | 内容 |
| --- | --- |
| サーバー接続 | ベース URL、Bearer トークン、接続テスト、自己署名証明書の信頼、自動同期の間隔／タイミング（起動時・毎朝の指定時刻・N時間ごと） |
| サーバーへアップロード | プロファイルを選んで「サーバーへ追加・アップロード」（§5.2） |
| サーバーからインポート | サーバーのルーティン一覧を表示し、選んで取り込み（§5.3） |
| Google アカウント連携 | サインイン／サインアウト、Tasks 取得間隔 |
| 祝日カレンダー | 地域（既定 `JP`）。今日ビューの祝日判定に使用 |
| ウィジェット | 大ウィジェットの表示件数、時刻フォーマット等 |
| 同期ログ | 直近の同期結果、競合発生の履歴 |

## 4. ローカルデータ（Room）

```
routine_profile
  local_id          INTEGER PK
  routine_address   TEXT NULL     -- 共有前は NULL、共有／インポートで確定し以後不変
  name              TEXT
  last_modified     TEXT          -- UTC RFC3339
  days_of_week      TEXT          -- "MON,TUE,..."
  holiday_policy    TEXT          -- exclude / include / only
  is_enabled        INTEGER
  schema_version    INTEGER
  is_shared         INTEGER       -- routine_address を持つか
  dirty             INTEGER       -- ローカル変更が未アップロードか

routine_block
  block_id          TEXT
  routine_local_id  INTEGER FK
  start_hm          TEXT          -- "07:00"
  end_hm            TEXT          -- "07:30"
  title             TEXT
  note              TEXT
  sort_order        INTEGER

task
  id                TEXT PK       -- サーバー採番 or ローカル生成
  source            TEXT          -- google_tasks / agent / manual
  external_id       TEXT NULL
  title             TEXT
  at                TEXT          -- タイムゾーン付き RFC3339
  all_day           INTEGER
  status            TEXT
  last_modified     TEXT          -- UTC
  deleted           INTEGER
  dirty             INTEGER

sync_state
  key               TEXT PK       -- "server" / "google"
  last_synced_at    TEXT
  last_task_cursor  TEXT          -- タスク差分取得の since 値

server_config
  base_url          TEXT
  token             TEXT          -- Android Keystore で暗号化保存
  auto_sync_mode    TEXT
  ...
```

- `routine_address` は **表示名と独立**。同名プロファイルが複数あっても別レコード・別アドレスとして扱う。
- `dirty` フラグで「ローカル変更あり → 次回同期でアップロード対象」を管理。

## 5. 同期の挙動

[`00-overview.md`](00-overview.md) §6 に準拠。端末側の具体手順を示す。

### 5.1 自動同期（通常）

トリガー: アプリ起動時 / 毎朝の指定時刻（WorkManager）/ 任意で N 時間ごと / 手動プル。

処理:

1. `GET /api/v1/routines`（`since` 付き）で一覧メタを取得。
2. **自端末が `routine_address` を持つ各プロファイル** について:
   - サーバーに同アドレスが存在し `last_modified` がサーバー側で新しい → `GET /api/v1/routines/{addr}` で取得し **ローカルを上書き**（開いている編集画面には反映確認を出す）。
   - ローカルが `dirty` かつローカルの `last_modified` が新しい → `PUT /api/v1/routines/{addr}`。`409` が返ったらローカルを「競合」マークし、同期ログに記録（自動 force はしない）。
   - サーバー側が tombstone → ローカルに「サーバーで削除済み」を表示（自動削除はしない）。
3. **サーバーにのみ存在するアドレス**（他端末が新規追加）→ 取り込まない。§5.3 のインポート候補として提示するのみ。
4. タスク同期:
   - `GET /api/v1/tasks?from=today&to=+Nd&since=<last_task_cursor>&includeDeleted=true` → `id` 単位で upsert、`deleted` を反映。
   - ローカルで `dirty` な手動タスク → `POST` / `PATCH` でサーバーへ反映。
   - エージェント由来タスクの完了操作 → `PATCH /api/v1/tasks/{id}`。
5. `sync_state` を更新。

競合時刻の基準: サーバー応答の `last_modified`（UTC）を正としてローカルに採用する。

### 5.2 手動アップロード（このルーティンをサーバーへ追加）

設定画面からの明示操作。仕様の中心機能。

1. 設定 →「ルーティンをサーバーへ追加・アップロード」→ ローカルプロファイルを選択。
2. そのプロファイルが `routine_address` を持たない場合、**256bit のランダム値を生成**（16進 64桁、`rt_` 接頭辞）してアドレスとして付与。以後この端末で不変・ローカル保存。
3. `PUT /api/v1/routines/{addr}` にルーティン全内容（`name` / `recurrence` / `blocks` / `lastModified`）を送信。
4. サーバー応答:
   - 未登録 → 新規追加（`201`）。
   - 既に同アドレスが存在（＝以前この端末から上げた）→ 更新扱い（`200`、件数は増えない）。
5. 成功したらプロファイルを「共有済み」にし、以後 §5.1 の自動同期対象に含める。

### 5.3 サーバーからインポート

1. 設定 →「サーバーからインポート」→ `GET /api/v1/routines` で一覧（名前・最終変更日時・アドレス断片）を表示。
2. 取り込むルーティンを選択 → `GET /api/v1/routines/{addr}` で全内容取得。
3. ローカルに同じ `routine_address` が既にある → 上書き確認の上で内容を更新。
   ない → 新規プロファイルとして作成し、**内容と一緒に `routine_address` も保存**。
4. 以後、そのアドレスを基準に §5.1 で双方向同期される。

これにより端末Aと端末Bが同じアドレスを共有し、A の編集 → アップロード → B の同期で B 側の同名アドレスのルーティンも更新される。

### 5.4 Google Tasks 連携

- Google Sign-In で認可（Tasks 読み取りスコープ）。
- WorkManager で定期取得（既定間隔は設定可、例：3時間 / 手動）。取得したタスクを `source = google_tasks`、`external_id = Google のタスクID` でローカルに upsert。
- Google Tasks は時刻を持たないことが多い → `due`（日付）を用い、時刻が不明なものは `all_day = true` として今日ビュー先頭にまとめる。ユーザーが端末側で時刻（`at`）を補完可能。
- 当面 **取得のみ**（Google への書き戻しはしない）。
- Google 由来タスクをサーバーへ転送するかは設定で選択（既定オフ：各端末が自分で取得）。

## 6. ホーム画面ウィジェット

今日ビューの計算（[`00-overview.md`](00-overview.md) §4.3）を本体と共有する。

### 6.1 小ウィジェット

- 表示: 「次のルーティン」（現在時刻以降で最も近い開始のブロック。進行中があればそれと残り時間）＋「次のタスク」（直近の `at`）。
- タップでアプリの今日ビューを開く。

### 6.2 大ウィジェット

- 表示: その日のルーティンブロックとタスクを時系列でまとめて一覧。現在位置インジケータ、進行中の強調。
- 件数が多い場合はスクロール、または設定した上限件数まで。
- ヘッダに日付と最終同期時刻。

### 6.3 更新契機

- 定期更新（例：15分ごと）。
- データ変更時（ルーティン編集、同期完了、タスク完了）。
- 時刻境界（次のブロック／タスクの開始時刻）に AlarmManager で更新し、「次の予定」表示が遅れないようにする。

## 7. オフライン動作

- ルーティン作成・編集・今日ビュー・ウィジェットはすべて **ローカルのみで完結**。
- サーバー同期・Google Tasks 取得は接続可能時のみ実行。オフライン中の変更は `dirty` としてキューされ、次回同期でまとめて送信。
- サーバー未設定でもアプリは単体で使える。

## 8. ネットワーク前提

- 接続先は共有サーバーのベース URL（LAN の IP、または VPN 接続時に到達できるアドレス）。
- 自己署名証明書 / 平文 HTTP（ローカル）を許容する設定を用意。
- 到達不可時はエラーを同期ログに記録し、ユーザー操作の同期では明示的に失敗を表示。

## 9. スコープ外 / 将来拡張

- プッシュ通知によるリマインド（将来）。
- Google Tasks への書き戻し、双方向同期（将来）。
- ルーティンブロックからの通知・アラーム。
- iOS / Wear OS。

## 10. 受け入れ基準（Android）

- [ ] 「平日」プロファイルを作成し、月〜金・祝日除外で今日ビューに時間帯ブロックが並ぶ
- [ ] 祝日に「休日（土日＋祝日）」プロファイルのブロックが今日ビューに出る
- [ ] Google Tasks を連携すると、取得したタスクが今日ビューにマージされる
- [ ] 設定から「ルーティンをサーバーへアップロード」でき、初回は 256bit のルーティンアドレスが割り当てられる
- [ ] 別端末で「サーバーからインポート」すると、内容とルーティンアドレスの両方が保存される
- [ ] 端末Aで編集・アップロード → 端末Bで同期すると、同じアドレスの端末B側ルーティンが更新される（新規に増えない）
- [ ] 競合時、より新しい `lastModified` の内容が採用される
- [ ] OpenClaw 等がサーバーへ追加した翌日のタスクが、翌朝の同期で端末に取り込まれる
- [ ] 小ウィジェットに「次のルーティン」「次のタスク」、大ウィジェットに今日の一覧が表示される
- [ ] 機内モードでもルーティン作成・編集・今日ビュー・ウィジェットが動作する
